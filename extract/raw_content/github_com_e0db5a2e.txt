### Summary

Summary

After upgrading OpenClaw to 2026.2.22-2, the OpenClaw Browser Relay extension shows:  

Gateway token rejected. Check token and save again. Even when the token entered in extension Options is exactly the same as gateway.auth.token in ~/.openclaw/openclaw.json.

Environment

• OpenClaw: 2026.2.22-2 (updated from 2026.2.21-2)  

• OS: Rocky Linux 10  

• Browser: Chrome (MV3 extension relay)  

• Relay port: 18792  

• Gateway local and running

### Steps to reproduce

1. Update OpenClaw to 2026.2.22-2.
2. Install/reload extension via:

• openclaw browser extension install  

• Load unpacked from ~/.openclaw/browser/chrome-extension

1. Open extension Options.
2. Set:

• Port: 18792  

• Gateway token: exact gateway.auth.token from openclaw.json

1. Click Save.

### Expected behavior

Token should be accepted (as implied by UI hint/docs: “Gateway token must match gateway.auth.token”).

### Actual behavior

Token is rejected with error:  

Gateway token rejected. Check token and save again.  

Extension badge remains in error state (!) and cannot attach.

### OpenClaw version

2026.2.22-2

### Operating system

Rocky 10, Gnome, Chrome latest

### Install method

npm global

### Logs, screenshots, and evidence

### Impact and severity

*No response*

### Additional information

Relay endpoint behavior indicates it currently expects a derived relay token (HMAC with context openclaw-extension-relay-v1:) rather than raw gateway token:

• /json/version returns 401 with raw gateway token header  

• /json/version returns 200 with derived token in x-openclaw-relay-token

Using the derived token in extension Options works as workaround.

Suggested Fix

Either:

1. Accept raw gateway token in extension Options flow (and derive internally), or
2. Update Options/docs/tooling to explicitly request/auto-generate derived relay token.
Reactions are currently unavailable
